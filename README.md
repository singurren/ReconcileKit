# 归账 ReconcileKit

这是我的个人账单预处理项目。

我最终想要的是一个越来越懂我个人账务习惯的 Agent：它能尽量自动帮我拿到账单，识别不同平台里的同一笔真实交易，判断这笔钱到底应该算支出、收入、转账、还款、退款还是投资划拨，然后把结果整理成钱迹和 Excel 可以使用的数据。

但这个目标不能一开始就写成承诺。银行、支付平台、电商平台未必有个人可用的官方 API，GUI 自动化也可能不稳定、受平台规则限制、容易触发风控。所以这个项目要把“最终想要什么”和“现在可靠做什么”分开。

## 我真正想解决的问题

我不想再手动把支付宝、微信、信用卡、电商订单、银行流水、邮件账单和 Excel 记录一点点对起来。

典型问题是同一笔真实交易会在多个地方出现：

```text
淘宝订单 300 元
→ 支付宝支付 300 元
→ 实际使用某张信用卡扣款 300 元
→ 信用卡账单里又出现一条支付宝快捷支付 300 元
```

这不应该被记成三笔支出。归账要做的是把它们归并成一笔真实消费，并保留来源、规则、置信度和审核记录。

归账不是新的记账软件。钱迹仍然是正式日常账本，Excel 仍然记录投资、项目、资产快照等个性化表格。归账只做落账前的数据整理。

## 长期方向

长期希望归账逐步变成个人化的自动 Agent：

- 自动或半自动获取账单；
- 自动解析不同来源的数据；
- 自动识别重复交易；
- 自动判断交易性质；
- 自动给出分类和 tag；
- 自动生成审核报告；
- 根据我的反馈沉淀规则；
- 对高置信度记录减少重复确认；
- 最终导出钱迹和 Excel 可用的数据。

这里的“自动”要分层理解。文件导入、邮件解析、规则匹配、报告生成可以逐步稳定自动化；银行和支付平台的抓取要看有没有官方接口、可导出文件、邮件账单、网页入口，以及 GUI 自动化是否现实。

## 现阶段先做什么

第一阶段先做稳定闭环，不把最不稳定的抓取能力放到主路径：

```text
账单文件 / 邮件 / 手动文本
→ 保存原始副本
→ 解析为原始记录
→ 标准化为统一交易
→ 匹配去重
→ 判断交易类型
→ 生成候选账单
→ 生成审核报告
→ 我确认或修正
→ 导出钱迹 / Excel 数据
→ 把我的反馈沉淀成规则
```

第一阶段优先支持：

- 支付宝账单文件；
- 微信支付账单文件；
- 信用卡账单文件；
- 淘宝 / 京东订单文件；
- 邮件账单或附件；
- 手动补充文本。

第一阶段不承诺：

- 稳定自动登录银行或支付平台；
- 全平台自动抓取；
- 无人值守跑完整流程；
- 自动处理验证码、人脸识别或风控确认；
- 自动写入钱迹正式账本。

## 自动采集怎么处理

我当然希望它以后能自动抓取账单，但文档里不能假装所有平台都开放了 API。

所以采集能力按现实程度分层：

1. **用户导出文件，归账自动处理**
   最稳，优先实现。

2. **邮件账单和附件解析**
   比较现实，适合作为早期能力。

3. **浏览器辅助采集**
   可以探索。前提是我自己登录、自己处理验证码和风控，Agent 只在已授权的只读页面里帮我读取、保存页面、点击下载账单等。

4. **截图 / OCR**
   可以作为补充能力，不作为主路径。

5. **GUI / App 自动化**
   作为长期探索，不写进 MVP 承诺。即使做，也要能人工接管，且只做读取和下载，不做任何资金操作。

6. **官方 API**
   如果某个平台真的提供个人可用 API，再单独适配。不预设它一定存在。

## 硬边界

这个项目不做这些事：

- 不保存支付密码、交易密码、短信验证码；
- 不绕过验证码、人脸识别或平台风控；
- 不自动提交转账、支付、交易、购买、赎回；
- 不修改金融平台上的任何数据；
- 不给投资建议；
- 不做预算规划；
- 不做消费分析 Dashboard；
- 不把低置信度交易直接导出为最终记录。

GUI 自动化如果以后做，也只能用于只读采集或辅助下载。涉及登录、验证码、风控、授权确认的地方必须由我自己处理。

## 核心原则

- 本地优先：原始账单、数据库、规则、审核日志默认放本地。
- 原始数据不可覆盖：所有处理结果都要能追溯回原始记录。
- 可审计：每条候选账单要知道来自哪些来源、用了什么规则、置信度是多少、我改过什么。
- 规则优先：金额、时间窗口、账户匹配、还款识别、退款关联等确定性逻辑不要交给 LLM 猜。
- LLM 辅助：LLM 适合做模糊商户识别、商品语义分类、自然语言反馈解析和报告说明。
- 低置信度必须审核：模糊、冲突、大额、新账户、新商户、新分类都要先让我确认。

## 推荐目录

```text
ReconcileKit/
  data/                 # 本地数据库，不提交真实数据
  raw_data/             # 原始账单归档，不提交真实数据
  rules/                # 账户、分类、匹配和导出规则
  imports/              # 导入批次状态
  reports/              # 审核报告
  exports/              # 钱迹 / Excel 导出结果
  logs/                 # 导入、匹配、导出日志
  agent/
    collectors/         # 采集入口：文件、邮件、浏览器、OCR 等
    parsers/            # 原始账单解析
    normalizers/        # 标准化
    matchers/           # 匹配和去重
    reviewers/          # 审核任务和反馈处理
    exporters/          # 钱迹 / Excel 导出
```

真实账单、数据库、导出文件、日志和原始项目定义不进 git。

## MVP 数据类型

候选账单至少要能表达：

- `expense`：支出；
- `income`：收入；
- `transfer`：转账；
- `credit_card_repay`：信用卡还款；
- `refund`：退款；
- `investment_transfer`：投资划拨；
- `fee`：手续费；
- `adjustment`：调整；
- `ignore`：忽略；
- `unknown`：未知，需审核。

几个原则：

- 信用卡还款不是支出；
- 投资划拨不是消费；
- 退款要关联原消费；
- 优惠券默认按实付金额处理；
- 不确定的交易进入审核。

## 阶段计划

### 阶段一：稳定的账单归并闭环

文件 / 邮件导入、标准化、匹配、候选账单、审核报告、钱迹 / Excel 导出、反馈规则沉淀。

### 阶段二：转账、还款、退款和投资划拨增强

增强银行流水、信用卡还款、退款关联、投资账户划拨和 Excel 投资台账更新。

### 阶段三：只读自动采集探索

探索浏览器辅助下载、页面保存、截图 OCR、GUI 只读采集。这个阶段的目标是减少我手动下载账单的成本，但不承诺所有平台都能稳定自动化。

### 阶段四：个人化自动 Agent

在足够多的真实使用反馈后，让系统逐步学习我的账户、商户、分类、tag 和审核偏好。高置信度事项可以减少打扰，低置信度事项继续让我审核。
