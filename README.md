# 归账 ReconcileKit

归账 ReconcileKit 是一个本地优先、可审计、半自动的个人账单归并 Agent，用于在正式记账之前整理多来源财务数据。

它的目标不是替代钱迹、Excel 或任何记账软件，而是作为落账前的数据中间层：从支付宝、微信支付、信用卡、电商订单、银行流水和手动文本等来源中提取交易记录，完成清洗、标准化、匹配去重、交易定性、人工审核，并导出为钱迹或 Excel 可以继续使用的数据。

## 项目定位

归账只负责四件事：

```text
导入 Import
标准化 Normalize
归并 Reconcile
审核 Review
导出 Export
```

它不负责：

- 正式记账；
- 预算规划；
- 消费趋势分析；
- 资产负债分析；
- 投资建议；
- 自动登录金融账户；
- 自动支付、转账、交易或购买；
- 完全无人值守的自动落账。

## 核心场景

同一笔真实交易经常会在多个系统里重复出现。

例如一笔淘宝消费可能同时出现在：

- 淘宝订单；
- 支付宝支付流水；
- 信用卡账单。

归账要做的是把这些记录识别为同一笔真实消费，并产出一条可审核、可追溯、可导入的钱迹或 Excel 数据，而不是把它们重复记成多笔支出。

## 设计原则

- 本地优先：原始账单、数据库、规则和审核日志默认保存在本地。
- 原始数据不可覆盖：导入后的处理结果必须保留来源引用。
- 可审计：最终候选账单应能追溯来源、规则、置信度和用户审核记录。
- 规则优先，LLM 辅助：金额、时间窗口、去重、还款、转账、退款等确定性逻辑优先使用规则和数据库逻辑。
- 低置信度必须审核：低置信度、规则冲突、账户不确定、语义模糊的记录不得直接进入最终导出。
- 不自动操作金融账户：项目只处理用户提供的只读数据，不执行任何金融操作。

## MVP 范围

MVP 目标是形成一个最小闭环：

```text
账单文件导入
→ 标准化交易
→ 匹配去重
→ 交易定性
→ 分类 / tag 建议
→ 生成审核报告
→ 用户确认
→ 导出钱迹 / Excel 数据
→ 保存反馈规则
```

优先支持的数据源：

- 支付宝账单；
- 微信支付账单；
- 信用卡账单；
- 淘宝 / 京东订单；
- 手动补充文本。

优先输出：

- `candidate_transactions.csv`
- `review_needed.md`
- `daily_report.md`
- `final_transactions.csv`
- `qianji_import.csv`
- `excel_updates.xlsx`
- `learned_rules.yaml`

## 推荐目录结构

```text
ReconcileKit/
  README.md
  data/                 # 本地数据库，不提交真实数据
  raw_data/             # 原始账单归档，不提交真实数据
  rules/                # 账户、分类、匹配和导出规则
  imports/              # 导入批次状态
  reports/              # 审核报告与日报
  exports/              # 钱迹 / Excel 导出结果
  logs/                 # 导入、匹配、导出日志
  agent/                # 解析、标准化、匹配、审核、导出模块
```

真实账单、数据库、导出文件和日志默认被 `.gitignore` 排除，避免个人财务数据进入仓库。

## 核心数据模型

MVP 阶段建议围绕以下表设计：

- `raw_imports`：记录每次导入批次；
- `raw_records`：保存原始账单记录；
- `normalized_transactions`：统一后的交易记录；
- `match_groups`：归并后的交易组；
- `match_group_members`：交易组成员；
- `candidate_entries`：准备导出的候选账单；
- `review_tasks`：需要人工确认的审核任务；
- `feedback_history`：用户反馈和规则沉淀记录；
- `export_batches`：导出批次；
- `export_records`：导出明细。

## 交易类型

MVP 至少识别以下类型：

- `expense`：支出；
- `income`：收入；
- `transfer`：转账；
- `credit_card_repay`：信用卡还款；
- `refund`：退款；
- `investment_transfer`：投资划拨；
- `fee`：手续费；
- `adjustment`：调整；
- `ignore`：忽略；
- `unknown`：未知，需审核。

其中信用卡还款不是支出，投资划拨不是消费，退款应关联原消费并冲减，无法判断的交易必须进入审核。

## LLM 使用边界

适合 LLM 辅助的任务：

- 模糊商户识别；
- 商品语义分类；
- 用户自然语言反馈解析；
- 规则草案生成；
- 审核报告说明；
- 异常原因解释。

不适合完全交给 LLM 的任务：

- 金额计算；
- 去重匹配；
- 账户余额校验；
- 信用卡还款识别；
- 投资划拨识别；
- 退款关联；
- 正式导出前的最终确认。

LLM 只能辅助判断和解释，不能作为账务事实的最终裁判。

## 开发阶段

### 阶段一：半自动账单归并 Agent

实现文件导入、标准化、匹配、分类建议、审核报告和钱迹 / Excel 导出。

### 阶段二：资产与转账增强

增强银行流水、信用卡还款、投资划拨、退款关联、Excel 投资台账和月末资产快照。

### 阶段三：谨慎的只读采集辅助

在不保存密码、不绕过验证、不执行交易的前提下，探索只读型 GUI 辅助采集或 OCR 辅助识别。

## 安全声明

本项目不保存支付密码、交易密码、短信验证码，不绕过验证码、人脸识别或风控验证，不执行转账、支付、交易、购买等金融操作。

所有真实账单和导出文件都应保存在本地，并在提交前确认不会进入 git 仓库。
