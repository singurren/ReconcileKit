# 归账 ReconcileKit

个人账单预处理项目。

目标是自动化账单抓取，识别不同平台里的同一笔真实交易，判断这笔资金流动的归属，生成可导入其他平台的记账数据。准备给钱迹和 Excel 用。

抓取账单先查银行、支付平台、电商平台有没有能用的接口。没有就看能不能导出文件、收邮件账单、走浏览器辅助、GUI 模拟、OCR。再不行就先手动导出替代。

记账归类、账户映射、tag、审核习惯等原则通过本地 md / yaml 文档记忆和学习。

现在麻烦的是来源太多。支付宝、微信、信用卡、电商订单、银行流水、邮件账单、短信、通知、Excel，每个地方都可能有一段资金流水。靠自己想起来去看不可靠，想起来了也要挨个打开、筛选、下载、确认，很容易漏。

所以抓取不是附加功能，是这个项目要解决的问题之一。不是只处理我已经整理好的文件，而是尽量帮我发现、获取、归档这些流水。能自动就自动，不能自动就半自动，再不行才手动导出。

同一笔真实交易经常会在多个地方重复出现，比如：

```text
淘宝订单 300 元
→ 支付宝支付 300 元
→ 实际使用某张信用卡扣款 300 元
→ 信用卡账单里又出现一条支付宝快捷支付 300 元
```

这不应该被记成三笔支出。应该归并成一笔真实消费，同时保留来源、规则、置信度和审核记录。

归账不是新的记账软件。钱迹还是正式日常账本，Excel 还是记录投资、项目、资产快照之类的个人表格。归账只做落账前的数据整理。

最后想把它用成一个个人化的自动 Agent：能抓账单、解析来源、识别重复交易、判断资金归属、给分类和 tag、生成审核报告，根据我的反馈慢慢记住规则。高置信度少问我，低置信度继续让我确认。

自动化分层做。文件导入、邮件解析、规则匹配、报告生成先稳定下来。银行和支付平台逐个看：接口、导出文件、邮件账单、网页入口、GUI 自动化。哪个平台能跑就先跑哪个。

先做一条稳定闭环：

```text
账单文件 / 邮件 / 手动文本
→ 保存原始副本
→ 解析为原始记录
→ 标准化为统一交易
→ 匹配去重
→ 判断交易类型
→ 生成候选账单
→ 生成审核报告
→ 人工确认或修正
→ 导出钱迹 / Excel 数据
→ 把反馈沉淀成规则
```

早期先接支付宝账单文件、微信支付账单文件、信用卡账单文件、淘宝 / 京东订单文件、邮件账单或附件、手动补充文本。

自动抓取这块先按平台拆。用户导出文件最稳，先做，但不是最终形态。邮件账单和附件也适合早点做。浏览器辅助可以试，自己登录，自己处理验证码和风控，Agent 在已登录页面里读取、保存页面、点下载账单。截图 / OCR 做补充。GUI / App 自动化后面再试，前提是能人工接管，只读、下载、截图，不碰资金操作。官方 API 先查一遍，能用就接。

抓取层要记每个平台最后一次检查时间、抓到了什么、失败原因是什么。至少能提醒我哪些来源还没看，哪些来源需要手动处理。

支付密码、交易密码、短信验证码不要存。验证码、人脸识别、风控不要绕。转账、支付、交易、购买、赎回不要碰。金融平台上的数据不要改。投资建议、预算规划、消费分析 Dashboard 也先不做。低置信度记录不要直接导出成最终数据。

GUI 自动化只用来采集或辅助下载。登录、验证码、风控、授权确认自己来。

本地优先。原始账单、数据库、规则、审核日志默认放本地。处理结果要能追溯回原始记录，来源、规则、置信度、人工修改都要留痕。金额、时间窗口、账户匹配、还款识别、退款关联这些确定性逻辑不要交给 LLM 猜。LLM 主要用在模糊商户识别、商品语义分类、自然语言反馈解析、报告说明。

推荐目录：

```text
ReconcileKit/
  data/                 # 本地数据库，不提交真实数据
  raw_data/             # 原始账单归档，不提交真实数据
  rules/                # 账户、分类、匹配和导出规则
  imports/              # 导入批次状态
  reports/              # 审核报告
  exports/              # 钱迹 / Excel 导出结果
  logs/                 # 导入、匹配、导出日志
  agent/
    collectors/         # 采集入口：文件、邮件、浏览器、OCR 等
    parsers/            # 原始账单解析
    normalizers/        # 标准化
    matchers/           # 匹配和去重
    reviewers/          # 审核任务和反馈处理
    exporters/          # 钱迹 / Excel 导出
```

真实账单、数据库、导出文件、日志和原始项目定义不进 git。

候选账单至少要能表达这些类型：

```text
expense              支出
income               收入
transfer             转账
credit_card_repay    信用卡还款
refund               退款
investment_transfer  投资划拨
fee                  手续费
adjustment           调整
ignore               忽略
unknown              未知，需审核
```

信用卡还款不是支出。投资划拨不是消费。退款要关联原消费。优惠券默认按实付金额处理。不确定的交易进入审核。

阶段先这么排：

```text
1. 文件 / 邮件导入、标准化、匹配、候选账单、审核报告、钱迹 / Excel 导出、反馈规则沉淀。
2. 增强银行流水、信用卡还款、退款关联、投资账户划拨和 Excel 投资台账更新。
3. 探索浏览器辅助下载、页面保存、截图 OCR、GUI 只读采集。目标是少手动下载账单。
4. 用得足够多以后，让它逐步记住我的账户、商户、分类、tag 和审核习惯。
```
