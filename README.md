# 归账 ReconcileKit

个人资金流水预处理 Agent。

目标：自动化采集多来源资金流水，识别同一真实交易在不同平台中的重复记录，判断资金流动归属，生成可导入钱迹和 Excel 的记账数据。

项目使用 Python 实现，依赖、虚拟环境、运行和测试统一交给 uv 管理。使用 uv 默认缓存，不在项目目录里放下载缓存。`.venv` 只作为项目虚拟环境。

账单采集按来源逐个适配：官方接口、平台导出文件、邮件账单、网页辅助下载、GUI 模拟、截图 / OCR。优先做稳定来源，不稳定来源保留人工接管。

账户、分类、tag、审核习惯、匹配规则等长期规则保存在本地 md / yaml 文件中，随使用持续调整。

资金流水来源包括支付宝、微信支付、信用卡、银行流水、电商订单、邮件账单、短信、通知、手动文本和 Excel。项目不只处理已整理好的账单文件，也要记录各来源的采集状态，减少遗漏。

典型归并场景：

```text
淘宝订单 300 元
→ 支付宝支付 300 元
→ 信用卡扣款 300 元
→ 信用卡账单出现支付宝快捷支付 300 元
```

以上应归并为一笔真实消费，而不是三笔支出。归并结果需要保留原始来源、匹配规则、置信度和审核记录。

归账不替代钱迹和 Excel。钱迹作为正式日常账本，Excel 记录投资、项目、资产快照等个性化表格。归账只做落账前的数据采集、清洗、归并、审核和导出。

第一阶段先跑通稳定闭环：

```text
账单文件 / 邮件 / 手动文本
→ 保存原始副本
→ 解析为原始记录
→ 标准化为统一交易
→ 匹配去重
→ 判断交易类型
→ 生成候选账单
→ 人工审核
→ 导出钱迹 / Excel 数据
→ 反馈沉淀为规则
```

优先接入支付宝账单文件、微信支付账单文件、信用卡账单文件、淘宝 / 京东订单文件、邮件账单或附件、手动补充文本。

自动采集作为独立能力推进。每个来源记录最后检查时间、采集方式、成功结果、失败原因和是否需要人工处理。浏览器辅助和 GUI 自动化只用于只读采集、页面保存、账单下载和截图，不做资金操作。

不保存支付密码、交易密码、短信验证码。不绕过验证码、人脸识别和平台风控。不提交转账、支付、交易、购买、赎回。不修改金融平台数据。低置信度记录不直接导出为最终数据。

确定性逻辑优先使用规则和数据库处理，包括金额比较、时间窗口匹配、账户映射、信用卡还款识别、退款关联、投资划拨识别、导出字段转换。LLM 用于模糊商户识别、商品语义分类、自然语言反馈解析、规则草案和审核说明。

推荐目录：

```text
ReconcileKit/
  pyproject.toml        # uv 项目配置
  uv.lock               # uv 锁定文件
  src/reconcilekit/     # Python 包
    collectors/         # 文件、邮件、浏览器、OCR、GUI 等采集入口
    parsers/            # 原始账单解析
    normalizers/        # 标准化
    matchers/           # 匹配和去重
    reviewers/          # 审核任务和反馈处理
    exporters/          # 钱迹 / Excel 导出
  data/                 # 本地数据库，不提交真实数据
  raw_data/             # 原始账单归档，不提交真实数据
  rules/                # 账户、分类、匹配和导出规则
  imports/              # 导入批次状态
  reports/              # 审核报告
  exports/              # 钱迹 / Excel 导出结果
  logs/                 # 导入、匹配、导出日志
```

真实账单、数据库、导出文件、日志和原始项目定义不进 git。

候选账单类型：

```text
expense              支出
income               收入
transfer             转账
credit_card_repay    信用卡还款
refund               退款
investment_transfer  投资划拨
fee                  手续费
adjustment           调整
ignore               忽略
unknown              未知，需审核
```

记账原则：

```text
信用卡还款不是支出。
投资划拨不是消费。
退款要关联原消费。
优惠券默认按实付金额处理。
不确定的交易进入审核。
```

阶段：

```text
1. 文件 / 邮件导入、标准化、匹配、候选账单、审核报告、钱迹 / Excel 导出、反馈规则沉淀。
2. 增强银行流水、信用卡还款、退款关联、投资账户划拨和 Excel 投资台账更新。
3. 探索浏览器辅助下载、页面保存、截图 OCR、GUI 只读采集。
4. 基于长期反馈学习账户、商户、分类、tag 和审核习惯。
```
