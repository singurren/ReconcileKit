# 归账 ReconcileKit

个人账单预处理项目。

目标是自动化账单抓取，识别不同平台里的同一笔真实交易，判断这笔资金流动的归属，生成可导入其他平台的记账数据。准备给钱迹和 Excel 用。

抓取账单先查银行、支付平台、电商平台有没有能用的接口。没有就看能不能导出文件、收邮件账单、走浏览器辅助、GUI 模拟、OCR。再不行就先手动导出替代。

记账归类、账户映射、tag、审核习惯等原则通过本地 md / yaml 文档记忆和学习。

## 问题

不想再手动把支付宝、微信、信用卡、电商订单、银行流水、邮件账单和 Excel 记录一点点对起来。

来源太多了。银行、支付软件、电商平台、信用卡、邮件、短信、通知、Excel 都可能有一部分资金流水。靠自己记得去看不可靠，就算记得，挨个打开、筛选、下载、确认也很麻烦。

所以账单抓取本身就是核心问题之一。不是只处理我已经整理好的文件，而是尽量帮我发现、获取、归档这些流水。能自动就自动，不能自动就半自动，再不行才手动导出替代。

典型问题是同一笔真实交易会在多个地方出现：

```text
淘宝订单 300 元
→ 支付宝支付 300 元
→ 实际使用某张信用卡扣款 300 元
→ 信用卡账单里又出现一条支付宝快捷支付 300 元
```

这不应该被记成三笔支出。应该归并成一笔真实消费，并保留来源、规则、置信度和审核记录。

归账不是新的记账软件。钱迹仍然是正式日常账本，Excel 仍然记录投资、项目、资产快照等个性化表格。归账只做落账前的数据整理。

## 想要的状态

最后想变成个人化的自动 Agent：

- 自动或半自动抓账单；
- 自动解析不同来源的数据；
- 自动识别重复交易；
- 自动判断交易性质；
- 自动给出分类和 tag；
- 自动生成审核报告；
- 根据我的反馈沉淀规则；
- 对高置信度记录减少重复确认；
- 导出钱迹和 Excel 可用的数据。

自动化分层做。文件导入、邮件解析、规则匹配、报告生成先稳定下来。银行和支付平台逐个看：接口、导出文件、邮件账单、网页入口、GUI 自动化。

## 先做

先做稳定闭环，抓取能力可以试，但不挡主流程：

```text
账单文件 / 邮件 / 手动文本
→ 保存原始副本
→ 解析为原始记录
→ 标准化为统一交易
→ 匹配去重
→ 判断交易类型
→ 生成候选账单
→ 生成审核报告
→ 人工确认或修正
→ 导出钱迹 / Excel 数据
→ 把我的反馈沉淀成规则
```

优先支持：

- 支付宝账单文件；
- 微信支付账单文件；
- 信用卡账单文件；
- 淘宝 / 京东订单文件；
- 邮件账单或附件；
- 手动补充文本。

先不写死：

- 稳定自动登录银行或支付平台；
- 全平台自动抓取；
- 无人值守跑完整流程；
- 自动处理验证码、人脸识别或风控确认；
- 自动写入钱迹正式账本。

## 账单抓取

目标是尽量自动抓账单。平台太多，手动巡检很容易漏，也很烦。

先按每个平台能拿到什么来做。

大概这么分：

1. **用户导出文件，归账自动处理**
   最稳。先做，但不是最终形态。

2. **邮件账单和附件解析**
   适合早做。

3. **浏览器辅助采集**
   可以试。自己登录，自己处理验证码和风控。Agent 在已登录页面里读取、保存页面、点下载账单。

4. **截图 / OCR**
   补充能力，不走主路径。

5. **GUI / App 自动化**
   后面再试。能人工接管。只读、下载、截图，不做资金操作。

6. **官方 API**
   先查一遍。能用就接。

抓取层要记录每个平台最后一次检查时间、抓到什么、失败原因是什么。这样至少能提醒我哪些来源还没看，哪些来源需要手动处理。

## 硬边界

不做这些事：

- 不保存支付密码、交易密码、短信验证码；
- 不绕过验证码、人脸识别或平台风控；
- 不自动提交转账、支付、交易、购买、赎回；
- 不修改金融平台上的任何数据；
- 不给投资建议；
- 不做预算规划；
- 不做消费分析 Dashboard；
- 不把低置信度交易直接导出为最终记录。

GUI 自动化只用来采集或辅助下载。登录、验证码、风控、授权确认自己处理。

## 核心原则

- 本地优先：原始账单、数据库、规则、审核日志默认放本地。
- 原始数据不覆盖：处理结果要能追溯回原始记录。
- 可审计：来源、规则、置信度、人工修改都要留痕。
- 规则优先：金额、时间窗口、账户匹配、还款识别、退款关联不要交给 LLM 猜。
- LLM 辅助：模糊商户识别、商品语义分类、自然语言反馈解析、报告说明。
- 低置信度先审核：模糊、冲突、大额、新账户、新商户、新分类都先人工确认。

## 推荐目录

```text
ReconcileKit/
  data/                 # 本地数据库，不提交真实数据
  raw_data/             # 原始账单归档，不提交真实数据
  rules/                # 账户、分类、匹配和导出规则
  imports/              # 导入批次状态
  reports/              # 审核报告
  exports/              # 钱迹 / Excel 导出结果
  logs/                 # 导入、匹配、导出日志
  agent/
    collectors/         # 采集入口：文件、邮件、浏览器、OCR 等
    parsers/            # 原始账单解析
    normalizers/        # 标准化
    matchers/           # 匹配和去重
    reviewers/          # 审核任务和反馈处理
    exporters/          # 钱迹 / Excel 导出
```

真实账单、数据库、导出文件、日志和原始项目定义不进 git。

## MVP 数据类型

候选账单至少要能表达：

- `expense`：支出；
- `income`：收入；
- `transfer`：转账；
- `credit_card_repay`：信用卡还款；
- `refund`：退款；
- `investment_transfer`：投资划拨；
- `fee`：手续费；
- `adjustment`：调整；
- `ignore`：忽略；
- `unknown`：未知，需审核。

几个原则：

- 信用卡还款不是支出；
- 投资划拨不是消费；
- 退款要关联原消费；
- 优惠券默认按实付金额处理；
- 不确定的交易进入审核。

## 阶段计划

### 阶段一：稳定的账单归并闭环

文件 / 邮件导入、标准化、匹配、候选账单、审核报告、钱迹 / Excel 导出、反馈规则沉淀。

### 阶段二：转账、还款、退款和投资划拨增强

增强银行流水、信用卡还款、退款关联、投资账户划拨和 Excel 投资台账更新。

### 阶段三：只读自动采集探索

探索浏览器辅助下载、页面保存、截图 OCR、GUI 只读采集。目标是少手动下载账单。哪个平台能跑就先跑哪个。

### 阶段四：个人化自动 Agent

用得足够多以后，让它逐步记住我的账户、商户、分类、tag 和审核习惯。高置信度少打扰，低置信度继续问我。
